# tessoku A03 two cards 添削

結論: 自分の回答は AC。以下は補足。

## 別解 (Rust らしい書き方)

ごく僅かにメモリは上がるが誤差。

```rust
let found = p.iter().any(|&i| q.iter().any(|&j| i + j == k));
println!("{}", if found { "Yes" } else { "No" });
```

## なぜ p・q どちらも参照の形 (&i, &j) になるのか

- `.iter()` は `&self` を取るメソッドなので、呼び出し自体がベクタを借用する
  (`for x in &vec` の `&vec` と同じ役割を `.iter()` が担っている)。
- そのため `p.iter()` / `q.iter()` はどちらも `Iterator<Item = &u32>` を返す。
- `i + j == k` は u32 同士の演算が必要なので、参照のままでは型が合わない。
  よって `|&i|`, `|&j|` というパターンで u32 の値を取り出す必要がある。
- p, q どちらも `.iter()` を使っている以上、扱いは完全に対称。

## なぜ引数は &i (参照) なのに、本体 (i + j == k) には & が要らないのか

- `|&i|` は「`&u32` 型の値をパターン `&i` で分解する」という分配束縛 (destructuring)。
  `let &i = 参照;` と同じ構造で、この時点で参照を剥がし、中身の u32 を i に束縛している。
- つまり引数リスト側で「剥がし方」を指定していて、本体ではもう剥がした後の
  u32 そのものを使っているだけ。だから & は不要。
- 剥がすタイミングを本体側に持っていくなら `|i| *i + ...` のように `*` で剥がす書き方も可能
  (その場合 i は `&u32` のまま)。
